# Muse 后台摘要：引擎实现与验证

后续同路由云端实验见[双 Muse minimal 验证](ITERATION-MUSE-CLOUD.zh-CN.md)；本页保留 Qwen/Muse 阶段结果。

本轮承接[第一阶段原型实验](ITERATION-MUSE.zh-CN.md)，将快照边界、字节预算和后台任务生命周期落实到引擎。所有后续 Muse 请求使用 `minimal`。宿主固定为 DSH `0.1.2-rc.1`。

## 行为与配置

默认仍使用确定性快换。仅显式配置 `backgroundSummary` 才会发出额外模型请求；该配置要求启用 windowed governor，准备线低于应急线。

```yaml
backgroundSummary:
  provider: opencode-go-muse
  model: muse-spark-1.3-contributor
  reasoningEffort: minimal
  prepareAtEffectiveCapacityPct: 0.6
  maxInputBytes: 262144
  maxOutputTokens: 2048
  timeoutMs: 60000
```

这些字段属于插件/bridge 的 `config`，不是模型工具参数。独立路由需由宿主已有配置提供。相同 provider 一律跳过；不同 provider 名称本身不能证明底层服务器独立，实验中使用本地 Qwen 与独立 Muse 服务。

1. 在真实 AgentLoop 请求进入 LLM 流时，读取最终请求路由和已记录的请求头/容量。rc.1 的 Web 选模不会更新 `agent.options`，且能覆盖较早的 request waterfall 值，因此不能用它们决定是否同路由。
2. 每会话、表面替换代次和前台路由最多准备一次。输入只取预算内完整、工具配对平衡的旧前缀；不为只有旧种子的前缀再发摘要请求。当前用户输入受保护。
3. 先装配来源说明、用户历史索引和精确记录索引，再把实际剩余 UTF-8 字节数交给摘要模型。模型输出必须完整、正常结束且全部装得下；超限整体拒绝。手写 `new_context` handoff 也改为超预算整体回退，账本与状态记录 `byte-budget`，不再截断尾部后仍标为模型辅助。
4. 只有安全 pre-step 会提交替换，完成回调从不修改会话。就绪摘要必须匹配会话、替换代次、当前/待选路由、连续前缀、来源哈希及字节预算。只替换摘要覆盖的前缀，后续新消息按原文保留。
5. 摘要未完成、超时、失败、取消、过期或回收空间不足，均立即走确定性回退。回收空间必须足以降到正常压力线以下；换后 55% 是软目标，不作为丢弃新原文的门槛。取消和销毁会 abort 请求并丢弃迟到结果。

`arc_status.backgroundSummary` 显示任务状态和字节额度；模型辅助窗口的账本另存来源末序号、哈希、摘要 provider/model/effort。旧账本仍可读。共享事务、主模型 shadow pricing 和归档检索机制保持原有约束。

## 真实验证口径

`tests/live/background-muse.mjs` 通过 rc.1 Web API 驱动安装后的引擎；观测插件只预载合成历史、限制探针工具和记录事件，不调用换窗或注入摘要。前台 Qwen 使用 `off`、2048 输出 token；摘要 Muse 显式 `minimal`。匹配机制试验为 64k 逻辑窗口、25% 准备线、4096 字节种子；另跑 50k 窗口、默认 60% 准备线的冒烟样本。前台完成后按宿主估算生成压力填充，触发真实 governor。这验证调度机制，尚未证明自主长任务的普遍收益。

种子探针还询问仅在快照之后出现的新标记；原文保留与答题分别计分。完整事件日志检查当前输入、工具配对、追加式写入、来源哈希、全部归档分页的逐字节恢复和本地请求串行。边界耗时为包围 pre-step 的观测区间，包含检查和持久化，不与上一阶段单独拆分的事务耗时混用。

三臂模型门继续使用 F3/91503、24 页、32k 压力、每批 6 页、相同简洁提示；原生 Basic 使用匹配阈值。Muse 的普通请求显式 minimal，实验私有 provider 配置也设 `reasoning: minimal`，覆盖 Basic 省略 effort 的摘要调用；观测器核对最终有效档位。

## 已保留的失败与修正

- 多个启动校准样本未生成辅助摘要，已主动停止并保留日志：初始请求缺少历史请求头，加上 Web 选模与 `agent.options` 不一致，导致启动条件错误。最终调度改用真实 LLM 流入口，AgentLoop 回归覆盖默认模型与实际请求不同的情况。
- 首次真实流重叠后，旧的严格 55% 门槛仍拒绝就绪摘要；种子 2/7、检索后 7/7，新消息被归档。该完整失败样本保留。回归现在要求“超出软目标但低于正常压力线”仍保留新原文。
- 超时故障样本暴露状态诊断问题：替换事件把已有 `timeout` 覆盖成了 `superseded`。最终实现只取消 pending/ready 任务，终态原因保持不变；回归和后续真实迟到样本验证了修正。原超时样本不改写。
- 全局设置不恢复：用户明确要求保留现状。本轮每次实验复制私有 settings，禁用自动标题模型调用，并核对全局文件哈希；日常 profile 不改。

## 引擎实测结果

下表覆盖全部 8 个完成样本。A 为确定性种子，C 为独立 Muse 后台摘要。分数为 7 个历史字段的严格匹配；“新原文”单独检查快照之后的 assistant 消息是否仍在活动窗口。种子阶段禁用历史检索，后一阶段允许检索。

| 样本 / 探针版本 | 种子直答 | 允许检索后 | 新原文保留 | 边界 ms | 允许尝试 / 确认成功 |
| --- | --- | --- | --- | ---: | ---: |
| A / 91521 / v1 | 2/7 | 7/7 | 否 | 9.59 | 6 / 6 |
| C / 91521 / v1 | 6/7 | 7/7 | 是 | 20.64 | 2 / 2 |
| C / 91522 / v1 | 5/7 | 6/7 | 是 | 10.59 | 2 / 2 |

| C / 91522 / v2 | 6/7 | 7/7 | 是 | 10.51 | 7 / 7 |
| C / 91523 / v2，50k / 60% | 7/7 | 7/7 | 是 | 10.60 | 0 / 0 |
| C / 91524 / v2，500 ms 超时 | 1/7 | 7/7 | 否，确定性回退 | 10.55 | 9 / 8 |
| C / 91525 / v2，延迟交付 | 2/7 | 7/7 | 否，确定性回退 | 11.15 | 28 / 18 |

v1 的 91522 失败来自输出附注：原始 `nextAction` ID 后被加上 `after approval`，严格评分仍记失败；没有发现对应来源事实丢失。v2 明确要求仅返回原始裸 ID，再做同配置 A/C 对照，未修改旧分数。所有样本均答对独立的新标记；A 的用户索引也能带出这个标记，因此答对标记不能证明 assistant 原文保留。

勘误：旧字段 `successfulRetrievalCalls` 实际统计的是守卫允许的尝试次数，不是工具成功结果。现更名为 `allowedRetrievalAttempts`；脱敏数据另从保留的最终事件推导结果状态。原始审计和分数均未改动。

四个就绪 C 样本都实际使用了 `model-assisted` 种子，只有其快照前缀进入归档；首个 Muse 请求耗时 **4.08–9.87 秒**，均与本地 Qwen 前台流重叠，未排进换窗等待。50k / 60% 样本只发出一次 Muse 请求。25% 准备线的三个就绪样本在后续代次又各发了一次准备请求，成本也计入数据；不能只统计被消费的摘要。

真实 500 ms 超时和延迟交付均立即提交一次确定性替换。延迟交付使用已完成的真实 Muse 响应，将结束块扣留 32.209 秒直到提交之后才释放；确认没有迟到写入或第二次窗口替换。其流耗时包含人为扣留，不用作模型性能数据。回退仍依靠归档恢复：迟到样本有 28 次允许尝试，其中 18 次确认成功，不能把“边界快”解读成“整段任务成本低”。

全部完成样本通过当前输入保护、工具配对、追加式事务、全分页归档逐字节恢复和 Qwen 请求串行审计；四个辅助种子的来源哈希都吻合。最小种子 1432 字节，最大 1771 字节。未发现摘要完成回调直接修改会话。

## 字节预算与回归

1 / 12 / 24 / 48 条历史用户消息压力下，真实紧凑 handoff 的 6 个字段全部保留，最终种子 3398–3663 字节。1300 字符的填充 handoff 在四例中均整体拒绝，记录 `byte-budget`，确定性种子 3897–3961 字节；这四例没有保留 handoff 的 6 个尾部字段，原文仍可检索。修复目标是消除静默截断和错误的“模型辅助”标记，不能让超预算内容凭空装下。

最终 `npm pack` 的 prepack 检查通过：**187 单元 + 105 宿主集成 + 15 本地执行器测试，共 307 项**，并通过 strict TypeScript 与构建。新增回归覆盖真实 AgentLoop 选模覆盖、跨轮 ready 消费、快照后消息保留、实际 UTF-8 余量、过期/超时/取消/销毁/迟到、同 provider 跳过和软目标。

## Muse minimal 三臂模型门

此组以 Muse 为前台，后台摘要默认关闭；验证新构件的常规换窗/原地压缩/原生对照，不与 Qwen 前台、Muse 辅助的机制组混合。原生与窗口首轮均保留失败，窗口仅额外按原配置复跑一次。

| 臂 | 耗时 s | 事实 | 修正 | 逐字 | 压缩/换窗 | 严格门 | 请求数 / reported token |
| --- | ---: | --- | --- | --- | ---: | --- | ---: |
| 原生 Basic | 102 | 23/24 | 6/6 | 1/3 | 3 | 失败 | 24 / 550289 |
| 插件原地压缩 | 49 | 24/24 | 6/6 | 3/3 | 3 | 通过 | 16 / 436600 |
| 插件换窗，首轮 | 66 | 24/24 | 6/6 | 3/3 | 3 | 失败 | 18 / 476363 |
| 插件换窗，原配置复跑 | 75 | 24/24 | 6/6 | 3/3 | 4 | 通过 | 24 / 657681 |

两次严格失败都含首批 6 次 `experiment_read_page({})`。实际请求 schema 要求整数 `page`，观测到的首轮参数增量合计仅 12 字符，后续事件也是六个 `{}`；守卫拒绝后模型才用正确页码重试。原生臂还存在答题错误。复跑首批参数增量为 60 字符，无拒绝调用。故障已定位到压缩发生前的工具调用输出，现有归一化流日志不能进一步区分服务端生成与宿主适配器；不放松守卫、不补写页码，也不宣称全部门通过。

四次运行都完整曝光 24 页且归档逐字节通过；两次窗口臂均通过真实进程重启。`new_context` 和 `compress` 主动调用仍全部为 0；7 次窗口替换全是 pressure / extractive。因此不能因 Muse 更强就假设它会主动做好交接。

## 结论与复现

当前可保留的实现是：**提前用独立 Muse minimal 准备有界摘要，边界只消费就绪且有效的快照，保留后续原文；其余情况立即确定性回退。** 默认关闭，未写入日常 profile。数据支持种子连续性收益与非阻塞边界，但样本小、历史合成，尚不能证明总体速度或费用更优：v2 的 C 检索 7 次，匹配 A 为 5 次。未验证双 Muse 并发、超长自主任务、真实 GPU 并行或其他模型。

[脱敏数据](data/turnover-muse-engine-2026-09-15.json)含每个样本的候选哈希、调用时间/token、故障和校准失败。原始数据在忽略目录 `.test-runtime/turnover-muse-20260915/` 与 `.test-runtime/nightly-20260915/muse-min-*`；第一阶段未指定 Muse 档位的数据单独保留。

```sh
export EXPERIMENT_DSH_BIN="$PWD/.test-runtime/host-pins/dsh-0.1.2-rc.1/node_modules/.bin/dsh"
# 安装前必须完成 prepack，目标仅限实验 profile。
npm pack --pack-destination artifacts
node tests/live/install-candidate.mjs ctx-v012-smoke-c
node tests/live/background-muse.mjs --name=engine-reproduce-c --arm=C --seed=91522
node --import tsx tests/live/background-audit.mjs .test-runtime/turnover-muse-20260915/engine-reproduce-c
node tests/live/local-short.mjs --name=muse-min-reproduce --route=muse --arm=C400_WINDOWED --family=F3 --seed=91503 --pages=24 --pressure=32000 --batch=6 --concise=true --restart=true
node --import tsx tests/live/local-audit.mjs .test-runtime/nightly-20260915/muse-min-reproduce
```

每次使用新的运行名。机制组 `--arm=A` 为对照；`--window=50000 --prepare=0.6` 检查默认准备线；`--fault=timeout` / `--fault=late` 检查回退。三臂另选 `A_NATIVE` / `B_IN_PLACE`。按次执行，本地 Qwen 不并发。
