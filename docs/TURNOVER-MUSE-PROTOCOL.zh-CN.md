# Muse 双路换窗验证协议（2026-09-15）

[English](TURNOVER-MUSE-PROTOCOL.en.md)

## 问题与边界

当前产品只有确定性换窗和主模型主动提交 handoff，没有后台摘要调度器。本轮先验证 **本地 Qwen 主模型 + Muse 独立摘要** 的可行性，再决定是否值得产品化。所有调度原型均在 `tests/live/turnover/`，不改变运行时或日常 profile。

宿主固定 DSH 0.1.2-rc.1；使用 `ctx-v012-mini-native` 路由冒烟、`ctx-v012-smoke-c` 已安装构件。保存源码、构件、设置文件哈希，日志只在忽略的 `.test-runtime/` 中。云端仅接收合成测试历史。

## 预先规定的实验

1. **兼容与重叠**：rc.1 的 Web 会话分别调用两条路由；三次同时提交本地前台工作与云摘要。以真实 `llm/stream` 的开始、首内容、终止时间计算重叠，不能仅凭 Promise 并行认定后端同时推理。
2. **固定边界三臂**：A 确定性种子；B 到换窗边界才调用 Muse 并等待；C 提前启动 Muse，边界只消费已经就绪的结果，否则立即回退并取消。每个种子三臂使用同一原文、主模型提示、边界与种子预算。计划三个合成种子，顺序 ABC / BCA / CAB。本地请求一次一个。
3. 历史通过宿主事件日志注入固定的合成工具调用/结果配对，因此这是**边界机制与连续性实验**，不是模型自主阅读长任务的端到端结果。前台工作和换窗后的回答调用真实模型。换窗通过已安装引擎的共享事务，在真实 `agent/pre-step` 安全边界提交；测试控制器强制同一边界，不把它记作模型主动采纳。
4. 18 页历史预估约 90 KB（执行后核对正文含分隔为 79,252 字节），包含抽取器能保留的精确结构化事实、分散在散文中的五项决策，以及明确要求摘要省略的逐字标记。前台工作后先测禁止检索的种子连续性，再开放历史检索。最新用户更正必须胜过旧摘要。第二个探针继承第一个探针，结果不作为独立样本。
5. 摘要绑定会话、代数、来源前缀哈希、序列边界及主模型路由；长度上限 1400 字符、请求输出上限 2048 token、超时 60 秒。记录实际进入种子的文本、原始字段保留率、换窗事务与等待时间、检索次数、请求 usage。usage 缺失记为缺失。
6. 故障验证：迟到、错误、超长、过期代数/来源/路由、取消、销毁；先覆盖调度状态机，再在真实宿主验证可执行的回退条件。摘要只在安全边界接入，迟到结果不得追写旧窗口。

## 判据

- 可行性：rc.1 能调用 Muse；真实流在至少一次样本中时间重叠，且两者完成。流重叠不等于服务器 GPU 并行证明。
- C 必须零等待摘要；真实换窗必须成功、保留当前输入、工具配对与可逆历史。所有失败样本保留。
- 比较 B/C 相对 A 的种子可答事实、最终正确率和历史检索成本；报告全样本，不以满分单样本或平均延迟掩盖退化。
- 只有质量/检索收益可见且关键路径代价受控，才建议继续产品化；三样本只是试点，不能声称统计显著、云服务并发上限或 400k 长程稳定性。
- 本轮不自动发布 npm，不修改默认模型或 preset 文件。

## 校准修订（正式三臂之前）

首个 A 校准样本保留为失败：Qwen 的默认 low 推理在禁止检索的诊断问题上耗尽 2048 输出 token，未产生答案。正式三臂统一显式选择 `reasoningEffort=off`，保留同一输出上限，不能将该校准样本并入正式配对。

同时发现 rc.1 `session/selectModel` 会写全局默认模型，profile 隔离不足以隔离 settings；正式执行器显式将 settings provider 指向每次运行的私有副本，并禁用测试宿主的自动标题模型调用，保证本地只有一条模型请求。首轮预检的默认项副作用单独记录并恢复，不伪称全程未发生修改。

第二个 A 校准完成但模型尝试了 5 次被拒绝的历史检索，因此正式诊断从声明层隐藏检索工具。空工具数组被本地 vLLM 以 HTTP 400 拒绝（另存失败）；最终保留 `arc_status` 声明并在执行层拒绝它，既满足适配器要求，也不向诊断提供额外事实。三个校准样本均单列；配对样本从 `paired-a-91511` 开始。

另补一组真实自主读取的 Muse 主模型三臂门：原生 Basic（匹配阈值）、原地压缩、窗口替换，F3/91503/24 页/32000 压力/每批 6 页/简短阶段答复。它验证现有产品路径，和上述测试调度器的 A/B/C 是两组不同实验。
