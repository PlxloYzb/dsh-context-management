# 夜间快速迭代 4（2026-09-15，候选 10：对抗性自查与原生对照）

[English](ITERATION-NIGHTLY-4.en.md) · [上一轮（候选 9）](ITERATION-NIGHTLY-3.zh-CN.md) · [下一轮（换窗统筹与实验设计）](ITERATION-NIGHTLY-5.zh-CN.md)

## 当前结论

本轮做两件事：对候选 9 做更激进的对抗性自查，并把原生 Basic 放到**同一触发点与同一保留量**上做真正的压缩算法对照。

自查发现并修复 1 处真实契约缺陷：`search_context` 的说明声称“检索摘要与原文”，但索引只覆盖归档原文。候选 8 的 `absent: true` 把这件事从“含糊”升级为**权威的错误结论**——写进检查点的短语会被判为“确实不存在”。修复是让说明与实现一致（索引只覆盖归档原文，摘要不被索引）。

自查中还尝试过“把检查点文本纳入索引”，但**被自己的留档数据否证**：新增命中全是模型在检查点里对原文的回声（`seq 335 tool/result: …`），并且实测挤掉了一条独立原文命中。该改动已撤销，只保留说明修复；ADV6 回归锁定“摘要回声不得进入索引、也不得挤掉原文命中”。

原生对照方面，旧 `A_NATIVE` 臂在本地 393216 容量下用默认 80% 阈值，从不压缩，因此不是压缩算法对比。新增 `--matched-native=true`：把 Basic 触发点设到插件的 32000 token 应急线、保留量设到插件换窗目标 19555 token（阈值 0.08138、保留 0.04973，都是 393216 窗口的比例）。匹配后**两次原生样本都没能完成任务**（一次 600 秒轮次超时，一次 25 分钟墙钟），压缩摘要的独立 LLM 调用分别吃掉 890/1026 秒与 1368/1500 秒；插件同夹具 24 页 174 秒读完、443 秒完成，事实 24/24、更正 6/6、逐字 3/3。

## 对抗性自查

| 攻击 | 结果 |
| --- | --- |
| 查询长度扫过片段预算边界（1…130 码位） | 通过：≤100 码位时被查字面量始终完整可见，片段不超 100 码位 |
| 行首由代理对组成（40 个 emoji） | 通过：前缀以自己的记录开头，不切断代理对 |
| CRLF 行尾 | 通过：前缀不落在上一行行尾，仍能指出记录名 |
| 归档为空 | 通过：不给出 `absent`（`inspected` 为 0） |
| 嵌套归档 + 先跑无关查询再做所有权去重 | 通过：真实命中不被去重隐藏，完整扫描仍可判 `absent` |
| 只在检查点里出现的短语 | **发现缺陷**：返回 `hits: 0, absent: true`；已改为如实说明，并由 ADV6 锁定摘要不进入索引 |
| 命中位于后段区块 | 通过：后段原文命中不会被误判为不存在 |

7 项对抗回归（ADV1–ADV7）全部通过；摘要索引的失败尝试只在私有目录留痕，不进入产品。

## 原生 Basic 匹配对照

夹具与压力：F3 / 91503 / 24 页 / 32k 压力 / 每批 6 页 / `--concise=true`，宿主 0.1.2-rc.1，路由为本机 Qwen3.8-27B-NVFP4KV-384K。

| 臂 | 触发与保留 | 读页 | 压缩 | 独立压缩 LLM 调用 | 压缩耗时 | 模型总耗时 | 质量 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 原生默认 80% | 314572 / 62914 token | 24 页，365 秒 | 0 | 0 | 0 秒 | 382 秒 | 24/24、6/6、逐字 3/3，通过 |
| 原生匹配 r3 | 32000 / 19555 token | 19 页后 600 秒轮次超时 | 5 | 7 | 890 秒 | 1026 秒 | 未评分 |
| 原生匹配 r4 | 32000 / 19555 token | 3 个阶段后 25 分钟墙钟 | 7 | 9 | 1368 秒 | 1500 秒 | 未评分 |
| 插件（本轮构件） | 换窗，应急线 32000，换窗目标 19555 | **24 页，174 秒** | 4 | **0** | 0 秒 | 458 秒 | 24/24、6/6、逐字 3/3，通过 |
| 插件（候选 5） | 同上 | 24 页，142 秒 | 5 | 0 | 0 秒 | 712 秒 | 24/24、6/6、逐字 3/3，通过 |
| 插件（候选 6） | 同上 | 24 页，146 秒 | 4 | 0 | 0 秒 | 496 秒 | 24/24、6/6、逐字 2/3，质量未全过 |

三条结构性差异：

1. **压缩成本的归属**。Basic 额外发独立的摘要 LLM 调用（每次 68–186 秒），匹配臂里占模型总时间的 87% / 91%；插件的摘要是智能体在同一轮里自己写的，独立压缩调用为 0。
2. **可逆性**。原生臂模型可用的工具里**没有任何历史检索工具**（无 `search_context`/`decompress`/`compress`/`arc_status`/`new_context`）；一旦 Basic 压缩，模型无法再取回原文。插件的命中片段与逐字探针正是靠这套工具在 4 次换窗后仍能答对。
3. **不压缩时原生更好**。夹具总量约 42k token，远小于 393216 的模型窗口；默认 80% 阈值下 Basic 根本不压缩，365 秒全过。插件在 32k 压力下主动压缩了 4 次——这是实验为了触发机制而人为缩小工作窗口，不是产品默认。

## 判定：够不够好

**在“必须压缩”的场景里，候选 10 明显优于原生 Basic，且已经足够可用；但它仍不是无损或统计意义上的优越。** 具体地：

- 够好的部分：同一触发点与同一保留量下，插件 24 页 174 秒读完、443 秒完成、事实/更正/逐字全过；原生两次都没能读完。可逆检索让 4 次换窗后仍能逐字答对。
- 不够好的部分：这些结论来自单样本模型运行（原生 2 次失败、插件 3 次里 2 次质量全过、候选 6 一次逐字 2/3），不能当作统计优势；32k 压力是人为设定；原生匹配臂是调过参的 Basic，不是出厂默认。
- 真正需要知道的前提：如果任务能装进模型原生窗口，Basic 不压缩、更快、同样正确——插件的价值只在压缩真正发生时体现。

  --seed=91503 --pages=24 --pressure=32000 --batch=6 --concise=true

# 插件对照臂
npm run test:live:local -- --name=<unique> --arm=C400_WINDOWED --family=F3 \
  --seed=91503 --pages=24 --pressure=32000 --batch=6 --concise=true

# 离线汇总与对照
node --import tsx tests/live/local-compare-runs.mjs <run> <run> ...
node --import tsx tests/live/local-native-comparison.mjs
node --import tsx tests/live/local-check-summary-gap.mjs
