# 总览：功能、优越性与历史

[English](OVERVIEW.en.md) · [返回首页](../README.md) · [设计](DESIGN.zh-CN.md) · [测试数据](TESTING.zh-CN.md) · [更新日志](../CHANGELOG.md)

一页看清 dsh-context-management 是什么、能做什么、哪些优势已被证据支持、哪些还没有。

## 它解决的问题

长任务里上下文只增不减。原生做法是把旧历史换成一段摘要，**原文就此消失**：摘要漏掉的路径、标识符、逐字值再也拿不回来，而模型的可用窗口又是硬上限。

本插件把"当前工作上下文"和"可查回的历史原文"分开：

- 当前窗口保持有界（换窗 / 就地压缩 / 有限超出三级降级）；
- 历史原文留在会话的追加式事件日志里，**不删除**；
- 模型可按预算检索、分页取回原文，并把结果当历史数据（不是新指令）使用。

## 功能

### 模型可见的工具

| 工具 | 作用 |
| --- | --- |
| `new_context` | 只提交换窗**意图**；真正的修改在下一次安全 pre-step 完成，保护当前用户输入与工具调用/结果配对 |
| `compress` | 把一个或多个已消费的表面区间换成自己写的稠密摘要；可批量、要求不重叠 |
| `decompress` | 按 blockId（+ 游标）只读取回某块原文；**不会**解除遮蔽 |
| `search_context` | 在当前会话历史里做**纯子串**搜索，返回命中与游标 |
| `arc_status` | 当前压力、持久块、可压缩区间、表面 seq 空间 |
| `await_context` | 仅在下一步确实缺历史时等待后台摘要；可继续独立工作。未配置后台摘要则不注册 |

### 引擎能力

- **两种策略**：`windowed`（默认，压力升高时推进新窗口，带连续性摘要）与 `in-place`（在当前窗口折叠旧内容）。
- **三级降级链**：换窗 → 就地可逆回退（提取式，**不调摘要模型**）→ 有限超出（记 `overshoot-within-physical-limit` 放行，而不是直接失败）。
- **软/硬压力线分离**：有效输入线与物理输入线分开，避免"预算悬崖"。
- **自适应保真**：摘要足够就直答；需要精确值或逐字原文时模型自主下探归档。
- **有界检索**：扫描量、返回量、分页游标都有上限；每轮检索有硬限额（引擎层保证收敛）；明确暴露不完整/错误状态。
- **可选后台摘要**：显式配置后，旧窗口提前准备带来源哈希的摘要；默认 `delivery: deferred`——换窗先提交确定性索引，摘要就绪后由宿主在后续 pre-step 追加，**不二次替换窗口**，也不会仅为交付摘要在最终答案后多发一次请求。
- **接管原生 Basic**：安装时启用目标 profile 的 bundle，由 bridge 在原生 Basic **原有的服务位置**上替换；`/compact` 走接管后的引擎，`/arc` 与 `/context` 提供状态。
- **不越界**：官方 `minimal` 没有原生压缩，保持不启用；第三方压缩后端保持原样；**不改写宿主预设文件**；卸载后宿主恢复自己的 Basic。

### 配置面（节选）

```yaml
adaptiveGovernor:
  strategy: windowed          # 或 in-place
  windowBudgetTokens: 203531
  maxOutputTokens: auto       # auto 保留显式输出意图，否则 32K；数字为硬上限
  safetyMarginTokens: 4096
  nudgeAtEffectiveCapacityPct: 0.75
  emergencyAtEffectiveCapacityPct: 0.9
  emergencyFallback: true
archive:
  seedMaxTokens: 4096
  retrievalDefaultMaxTokens: 2048
  retrievalMaxTokens: 4096
backgroundSummary:            # 不配置即关闭
  provider: opencode-go-muse
  model: muse-spark-1.3-contributor
  reasoningEffort: minimal
  allowSameProvider: false    # 同 provider 并发需显式 true
  delivery: deferred          # 或 seed（对照用）
  prepareAtEffectiveCapacityPct: 0.6
  maxInputBytes: 262144
```

另有 `autoTools` / `autoCommand` / `autoNudge`、`protectedRecentMessages`、`minCompressChars` 一类的保护与门槛项，以及可整体覆盖的提示词模板。

## 优越性：哪些已被证据支持

### 1. 无损可逆 —— 结构性的、原生做不到

**最强的一组证据（0.8.6，完全相同的条件：seed 91501、144 页、F3、batch=12、muse 路由）：**

| 臂 | PAGE-11 | PAGE-46 | PAGE-89 | 得分 | 压缩次数 |
| --- | --- | --- | --- | --- | --- |
| **B_IN_PLACE（插件）** | `ae3790159a` | `6da15bef1b` | `0972779886` | **3/3** | 3 |
| **A_NATIVE（原生 Basic）** | `null` | `null` | `null` | **0/3** | 9 |

两臂的 `strictPassed` 都是 true、facts 24/24、corrections 6/6、`deliverablePassed: true`——**权威事实原生也保得住**。verbatim 探针问的是**已被压缩掉的精确历史字面量**：原生无法还原，插件三个校验和逐字节全中。原生臂的 0/3 已逐项排除假阴性——它是一个键名完全正确的良构对象，模型听懂了问题并如实报告"不可得"。

**结论精确到这一点：插件的收益不在"保住权威事实"（原生也能做到），而在"精确历史可检索"。**

150k 迭代的最终对照（同任务、同评分、本地 Qwen 串行单旅程）是同一结论的第二组证据：

| 臂 | 配置 | P1 事实/更正 | P2 逐字 checksum | token |
| --- | --- | --- | --- | --- |
| A 原生默认 | Basic @ 314,573 | 24/24 + 6/6 | **0/3**（无检索能力） | 8.99M |
| B 原生校准 | Basic @ 150,000 | 24/24 + 6/6 | **0/3** | 6.05M |
| **C 插件（修复版）** | windowed W=203,531 | **24/24 + 6/6** | **3/3**（7 次检索） | **5.9M** |

注意这是**单旅程工程证据，不是统计确证**。

### 2. 事实召回不劣化

27 个固定合成样本（3 种子 × 3 次 × 3 臂，`opencode-go/glm-5.3-flash`）：

| 策略 | 完成 | 重启前召回 | 重启后召回 | 重启后保留更正 | 逐字取回 |
| --- | --- | --- | --- | --- | --- |
| A 宿主 Basic | 9/9 | 108/108 | 108/108 | 9/9 | 9/9 |
| B 插件 in-place | 9/9 | 108/108 | **98/108** | **4/9** | 9/9 |
| **C 插件 windowed（默认）** | 9/9 | 108/108 | 108/108 | 9/9 | 9/9 |

默认的 `windowed` 与原生打平；`in-place` 在重启后明显更差——所以默认是 `windowed`，`in-place` 只作为可选配置保留。**不据此主张成本更低或更快。**

## 优越性：哪些**没有**被证明

这一节比上一节更重要。

- **400k 实验（180 条预注册队列）没有得出任何确证性结论。** 官方终局报告原文：C 臂 35 次真实尝试中 **28 次**死于"保留输入超过有效预算且无安全可减区域"（真实口径严格完成率 17.1%，而 A 70.0%、B 69.7%）。预注册的确证门槛全部不可评估——180 条里 82 条是基础设施失败。**"质量非劣 / 更优 / 更便宜 / 更快"都不成立。**
- **成本与速度从未被主张。** 时间比 C/B = 0.52 被明确标注为不可解读为效率优势（C 的"更快"来自失败得早）。
- **真实供应商物理溢出未触发验证**；受控 loop 溢出测试不能替代它。
- **3M 长程实验已设计但尚未执行**（协议与机器计划已就绪）。
- 其他宿主版本、模型、HMR、无限层级嵌套不在已有数据的覆盖范围。

这些边界都写在 [400k 终局报告](EXPERIMENT-REPORT.zh-CN.md)与[测试数据](TESTING.zh-CN.md)里，没有藏起来。

## 历史时间线

96 次提交、45 个版本。按实际变更归档：

| 阶段 | 版本 | 发生了什么 |
| --- | --- | --- |
| 起点 | 0.1.0 → 0.1.1 | 首版：可回溯压缩、自动换窗、历史检索、手动命令；随后自动接管目标 profile 内各 preset 的原生 Basic（含自定义行名、嵌套结构、preset 切换） |
| **失败与总修复** | **0.2.0** | 400k 实验收束后的一版大修复：后台摘要在已安装布局下从不启动的门判据、Basic 接管生命周期边界、后台摘要默认改为 `delivery: deferred` 并新增 `await_context`、新增 `allowSameProvider`；Muse 云端短分页验证的诚实结论是 **0/4 次采用** |
| 检索索引 | 0.3.0 → 0.6.1 | 3-gram 块过滤；修掉"把存在的原文误报为不存在"的 Unicode 大小写缺陷；索引改为按唯一原始事件键控并增量构建（封存归档首次建索引从 7,426 万字符降到约 268 万唯一原文）；索引缓存按会话保留 64 份并支持淘汰/销毁/重建；新增 `index: false` 纯扫描回退开关；补齐三种游标情形 |
| 计量 | 0.7.0 | 合同 §7 工作量计量落地：冷/热/翻页三档成本与命中分开报告 |
| 压测-修复循环 | 0.7.1 → 0.9.6 | 压力地板标定（并更正"地板是单一数字"的过强结论）；修掉 in-place 应急回退一回合内无限重复、以及"每次都有进展却永不收敛"；windowed 臂补上每回合上限；修掉三个把正确回答判成 0 分的计分假阴性；0.9.0 挖出并修掉紧急回退"进度"判据本身的错误；0.9.5 三臂门禁取得两个插件臂 **18/18 满分** |
| **决定性对照** | **0.8.6** | 完全相同条件下分别跑原生臂与插件臂：**原生压缩销毁精确历史，插件完整还原**——verbatim 探针原生 0/3、插件 3/3 |

| 移植 | 0.9.10 / 0.9.11 | 两个引擎修复各重复验证一次；移植到 DSH 0.1.7-rc.1（source kind、surfaceOp、system/message、preset registry 等破坏性变更）；真实宿主端到端验证 |
| **本轮** | **0.9.12** | peer 范围改 `^0.1.7-rc.1`（原先精确锁定 rc.1 导致 rc.2 **装得上但起不来**）；新增跨宿主回归门；修掉受保护系统头、压缩事务收尾、夹具真实性三类缺陷；rc.1 与 rc.2 双双端到端通过 |

## 一句话取舍

**它不承诺更快或更便宜，也不承诺比原生压缩更聪明。** 它承诺的是：原文不丢、可按需取回、当前窗口有界、降级路径明确、装上能接管、卸下无残留——并且在 2M token 级长旅程上**曾被证明撑不住**之后，把那些结构性缺陷逐条修掉并留下了回归测试。
