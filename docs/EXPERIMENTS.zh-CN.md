## 1. 要回答的问题与结论边界

1. 与原生 Basic 相比，插件在长任务完成率、最新事实保留、历史取回、恢复可靠性上是否至少不差？
2. 在相同 400,000 token 压力线附近介入，插件是否改善成本或耗时？改善是否仅来自更早处理上下文？
3. 400k 策略能否跨多个窗口稳定运行，何时只是修剪、何时实际换窗、是否存在反复无收益换窗？
4. 事务、取消、崩溃、安装和卸载是否保持宿主约定？故障时能否明确暴露不完整状态？

历史 0.1.1 的 Basic/windowed 都曾达到 108/108 召回；预算不同、路由不同，不能据此证明插件更好，也不能作为本实验的对照样本。本实验不预设胜者。报告允许“质量相当但更贵”“证据不足”“400k 条件不成立”。

原生 Basic 已保留追加式原始日志；“保留原文”本身不是独有优势。插件的可检验差异是模型表面管理、窗口交接、历史访问和这些机制的总体代价。本方案中的 400k 是 **400,000 十进制 token**，表示宿主估算的当前请求输入压力，不是会话累计用量、账单输入量或 409,600 token。

## 3. 400k 的精确定义与组配置

当前实现的公式见 [governor.ts](../src/governor.ts)：

```text
E = min(C, windowBudgetTokens) - R - S
提示线 N = floor(E × 0.75)
应急压力线 T = floor(E × 0.90)
```

固定 R=32,768、S=4,096 时：

| 逻辑窗口配置 | E | N | T |
| --- | ---: | ---: | ---: |
| 400,000 | 363,136 | 272,352 | 326,822 |
| 481,309 | 444,445 | 333,333 | 400,000 |

第二行要求 **C ≥ 481,309**。若该路由实际容量更小，本协议的 400k 主实验标记 BLOCKED；可以继续离线可靠性测试，但不能把较小窗口实验当作完成 400k 验证。第一行只是公式说明，不是主实验的组配置。

插件 C400 的配置片段如下，须由隔离 profile 的覆盖层作用于现有 bridge；不是新增 CLI 参数，也不写入预设文件：

```yaml
adaptiveGovernor:
  enabled: true
  strategy: windowed
  windowBudgetTokens: 481309
  maxOutputTokens: 32768
  safetyMarginTokens: 4096
  nudgeAtEffectiveCapacityPct: 0.75
  emergencyAtEffectiveCapacityPct: 0.90
  targetAfterTurnoverPct: 0.55
  emergencyFallback: true
```

必须另外验证主请求实际 `maxTokens=32768`。`maxOutputTokens` 数字策略是上限，调用者设置更小值时实际 R 仍可能更小，导致 T 改变。`targetAfterTurnoverPct=0.55` 是记录目标，不是当前实现保证达到的硬后置条件。

| 新组 ID | 后端及配置 | 用途 |
| --- | --- | --- |
| A_NATIVE | 原生 Basic；`auto=true`、默认 `thresholdRatio=0.8`、`retainRatio=0.16`、摘要 `maxTokens=8192`，输出 R 同上 | 与原生默认压力策略比较；若 C=1,000,000，压力线约 800k |
| B400_BASIC | 同一 Basic，仅将比例校准为 `400000/C`，使用其真实取整公式验证阈值正好 400,000；其余配置与 A 相同 | 控制“更早介入”的影响 |
| C400_WINDOWED | 当前候选插件，上述 governor，归档 seed=4,096、默认取回=2,048、最大取回=4,096 | 检验完整窗口策略 |

B 的默认保留量 `floor(0.16×C)` 必须小于 400,000；若不成立，先修订共同的保留配置并重新冻结，而不是让 B 用无效配置参赛。Basic 比例的浮点乘积若向下取整得到 399,999，校准最小增量并记录最终解析值和有效阈值。

默认修剪器三组一致：`thresholdChars=8192 / headChars=4096 / tailChars=1024`，核对实际加载值与 Unicode 计数语义。长语料须分成低于修剪阈值的小结果，避免输入尚未达到 400k 就被修剪掉；大结果另设专门场景。

C/B 对比控制压力线，**不能完全隔离单个算法变量**：C 在 333,333 可提示模型，历史工具、保留策略和摘要方式也不同。A/C 反映整套产品策略差异；C/B 反映大致匹配压力线后的策略差异。记录各组实际保留量和工具列表，不能声称所有请求完全相同。原生组不能调用插件专有历史工具；三组一般文件/执行工具相同。

### 压力触发不等于严格在 400k 换窗

检查发生在安全 pre-step；先修剪再重测，压力降低后可能无需换窗。模型也可能更早主动 `compress` 或 `new_context`。一次大工具结果可能越过阈值；没有可安全移出的区域时会报预算错误。因此当前版本不承诺“绝不超过 400k”，也没有独立的绝对输入换窗阈值开关。

每次压力决策记录 `inputBefore → afterPrune → afterCommit → finalRequestInput`、N/T/R/S、测量基线、触发原因、是否提交、延期原因、窗口 ID 和 seq。所有组记录压缩事件；只给 C 统计真正窗口提交。阈值偏差用 `max(0,inputBefore−T)`，实际发送的逻辑超限另用 `max(0,finalRequestInput−E)`，不能混为一谈。确定性边界验证与允许模型自主行为的任务实验分开。

## 4. 分阶段执行与有限样本量

| 阶段 | 数量与执行内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0 静态与契约 | 全部现有回归、真实宿主受控集成、下文离线案例；不调用供应商 | 零数据完整性/路由配置缺陷，执行器审计通过 |
| P1 校准试跑 | 6 个任务（每族 1 个独立试跑种子）×3 组×1 次 = 18 条完整会话 | 容量和实际400k压力可达、所有调用路由正确、评分与限额可用；不纳入正式统计 |
| P2 正式主实验 | 6 族×5 个正式种子=30 个独立任务；每任务2次×3组 = **180 条完整会话** | 固定样本全部终态；按下述规则评分，不因中途显著而提前宣布成功 |
| P3 扩展 | 真实 Web 故障恢复、可选消融/剂量、规模与生命周期 | 与主实验分表，未执行项目显式列出 |
| P4 审计与报告 | 重放源文、验证请求配对、复算评分/统计、核对安装产物 | 证据可追溯；失败与缺失均保留 |

试跑可用于修复执行器、估计变异和预算；正式运行前冻结 v1 的最终执行 revision。默认 30 个任务不保证统计功效。根据试跑的配对方差/不一致率对 5 个百分点的质量界限、10% 的效率差异做功效模拟并保存脚本和输出；若预算不足以达到目标 80% 功效，仍可按 180 会话执行，但必须提前标记功效不足，不能事后扩大样本直到显著。扩大样本需先形成新协议并固定样本数。

正式种子按 `10000 + 100×familyIndex + variantIndex`，familyIndex=1..6，variantIndex=1..5；试跑种子 `90000 + familyIndex`，与正式集合不重合。重复次数为 1、2；随机化种子 904009。30×2 个配对块使用 A/B/C 的六种顺序，各10次，通过固定洗牌分配。主实验默认同时只有一条模型会话运行；组内顺序交错，禁用历史结果重用。性能测试单独测并发。

每任务语料是预生成、不可被模型改写的固定清单；三组每个配对块使用相同材料和节奏，不按某一组换窗次数临时增加页数。长任务目标为约 **2,000,000 新增输入估算 token**（不含重复发送历史），分成约 20k 的阅读批次，各批多个小工具结果。以试跑测量冻结字节数、页数和哈希；供应商 token 用量与宿主估算分别记录。不能只写入 2M token 文件却不验证其实际被工具读取、进入请求。

至少每族 4/5 个任务是长任务，剩余1个为 80k–150k 短任务，检查低压力开销。正式语料长度由独立试跑冻结，禁止根据正式表现调整。长任务预期 C 至少3次实际换窗；未发生不能自动剔除：记录原因并标记该项多窗覆盖不足。短任务不要求换窗，不算该覆盖分母。

## 5. 六类任务、答案与完整旅程

| 族 | 输入及干扰 | 可确定验收的交付物 |
| --- | --- | --- |
| F1 精确事实与更正 | 中英混合路径、ID、单位、数字，旧值/撤回/两次更新，早中晚分布 | 24字段精确 JSON；其中6项以最后有效更正为准 |
| F2 代码维护 | 合成仓库中的故障、跨文件依赖、历史决定、后续约束变更 | 最终补丁通过隐藏功能测试、未破坏禁止修改的文件、满足最新需求 |
| F3 排障分析 | 多服务日志、假线索、跨页时间线、失败尝试和后续纠正 | 根因 ID、事件顺序、修复选项和原始出处；按预制规则评分 |
| F4 结构化工作流 | 表结构/接口演进、依赖先后、未完成步骤、串并行工具往返 | 最终状态机及接口验证器通过，不重复产生有副作用的合成操作 |
| F5 历史检索与歧义 | 同文本不同 seq、相似/重复 ID、嵌套归档、旧窗口证据、无答案问题 | 精确值+源 seq，歧义/缺失明确；不可从提示猜出答案 |
| F6 交接与恢复 | 长调查、当前用户新约束、未完成工具批次、跨轮未完成目标 | 重启前后交付物、待办和最新约束一致，工具调用成对 |

每个任务同时有24个历史事实（6个更正字段）及该族交付物验证器。生成器为每个种子更换值、位置和干扰项；不靠重复无信息日志撑满窗口。早/中/晚位置各占三分之一，至少1/3事实在预期首轮处理前、1/3涉及多段关联。更正和撤回写成明确合成用户指令，历史不可信文本另加来源标记。

旅程固定为：创建隔离会话并选择路由 → 投放首段任务与事实 → 分批读取、执行族任务 → 25%/55%/80%进度投放更新 → 完成全部阅读 → 盲测 Q1及交付物 → 等待落盘、记录最终 durable seq → 真实停止并重启 DSH进程 → 恢复同 session ID → 盲测 Q2及最新约束 → 独立源文重放与配对审计。

Q1/Q2 不含参考答案或正确性反馈。Q2结果标记“经历过Q1后的重启恢复”，不冒称独立无提示记忆实验；崩溃专项另设未做Q1的恢复任务。评分程序与隐藏答案放在模型不可见的独立目录，不经工具结果、系统提示或归档索引泄漏。

F1/F5及所有历史事实盲测禁止重读语料文件/联网获取答案，必须由执行器限制工具权限并记录尝试，不能只依赖文字要求。F2允许访问工作代码但不允许打开评分器/历史答案；历史事实与代码中可读信息分离。插件可用其历史工具，原生用其现有能力，独立验证器可以读取原始日志但不能把结果提供给模型。

## 7. 评分与指标

评分器先用人工构造的正确/错误/缺字段/多JSON/Unicode/撤回/超时样本验证，再冻结；不使用参赛模型或另一个LLM判定主指标。

- **Q（共同主要质量指标）**：每个任务的两次重复先取平均，再跨30个任务等权。单次严格完成=Q1/Q2均满足该族隐藏验证器、至少23/24事实精确正确、6/6最新更正正确、无禁止操作、无不可恢复错误；否则为0。
- **事实与更正**：同时报告Q1/Q2的逐字段正确率、全部6项更正正确的会话比例，以及无答案问题的误报率。字符串按JSON解码后的精确值比较，不翻译、不大小写归一、不以正确程度挑JSON对象；沿用最大字段覆盖、并列选最后的确定性规则并冻结版本。
- **原文完整性**：独立于模型答案，对本轮所有归档源分页拼接后比对原始字节/hash及seq；没有归档记N/A及原因，不能用0次检查声称取回100%。保留“能取回却没答对”的区别。
- **效率**：完整旅程墙钟时间（包括重启、检索、重试）、首次响应、pre-step阻塞、换窗耗时、每请求输入/输出、缓存读写、所有辅助调用、检索次数/返回tokens、重试和请求数。成功配对样本的延迟单列，不能掩盖失败或超时。
- **费用**：按每次供应商返回的usage语义计算，先核对输入是否已含缓存，再套执行当日冻结的价格来源；主调用、摘要、失败的可计费调用均纳入。字段缺失记null+missingCount，不当0、不虚构美元成本。API不提供完整usage时仅报告可核实token与时长，费用优势结论不可用。
- **请求预算**：比较每次宿主估算与可用实际usage；未知不是0。统计压力线偏差、最终逻辑/物理预算超限、无收益处理、窗口数和原文/交接/重注入快照各自体积。

所有尝试纳入账单。失败会话的Q=0，未回答事实=错误；已答对的分项保留。完整旅程时间对未完成样本取冻结的会话超时上限作为惩罚值；同时报告实际花费时间和失败率。成本以“整组全部尝试花费/严格成功会话数”报告，0成功记不可用；另给每个已分配会话成本，避免廉价失败显得更优。

## 8. 统计规则与“更好”的门槛

统计单位是 **30个独立任务**，不是720个事实，也不是60条重复会话。以任务为cluster，保留组间配对及两次重复，进行20,000次配对cluster bootstrap，随机种子904010。主要质量差值为 `Q(C)−Q(A)` 和 `Q(C)−Q(B)`；两项分别报告97.5%双侧区间，作为两比较的保守多重校正。bootstrap出现退化区间（包括全相同结果）时，非劣推断标记为证据不足，须另行设计样本量充分的实验；不能以零宽区间声称已经证明等价。统计实现和模拟校验在P1冻结。

**质量门槛**：C严格完成率≥90%；两项质量差区间下界均≥−0.05；C全程更正正确会话率≥95%；C原文完整性、工具配对和会话隔离无一次违反。若区间过宽，结论是“非劣证据不足”，不是“差异不显著所以一样好”。原始得分与子族分数必须公布。

只有质量门槛成立后检验对B的两项效率主张：每严格成功的总成本比、带超时惩罚的平均完整旅程时间比。对每项以相同配对cluster方式给97.5%区间，上界≤0.90才称该项“至少改善10%”；成本缺字段时成本检验不可用。p95、A/C效率、族内差异和消融属于描述性/探索性，不能替换未通过的主指标。

对外可声称“在指定路由、宿主与这组任务上，保持预定质量界限并降低X”，须同时满足上述质量和至少一项效率门槛。若仅质量提高，可报告质量差及区间，不冒称更便宜或更快。即使三组都满分，也只说明此任务集未区分质量，不能外推全模型/所有长任务。

可靠性发布门槛与产品优越性分开：P0、适用的R01–R15/R17–R19无未解决完整性缺陷是发布前提；R16未触发不妨碍如实报告受控覆盖，但禁止声称真实物理溢出已验证。任何必测项BLOCKED/NOT_EXERCISED须列入结论，不能统称“全方位测试通过”。

## 9. 失败、重试、时间和预算纪律

P1后固定单请求、单轮、整会话超时；最初试跑上限分别为300秒、20分钟、4小时，并发1。正式上限由试跑p90及服务限制决定，按所有组共同值写入冻结manifest。若试跑需要提高上限，保留原超时记录并先更新revision。

执行器不静默重跑。失败分类：任务/模型答案、插件/宿主、供应商429/5xx、网络/驱动、路由错配、配置、预算停止、人工中止；原始attempt ID不可覆盖。正式已分配样本均保留：请求已发出或无法证明未发出，计入主要分析；明确未发出任何模型请求的基础设施失败可以在相同样本下补一个有新ID的执行attempt，但保留原失败、原因和费用核对。供应商重试由各组相同且冻结的传输策略控制，所有重试计数/计费；不准因答案不好重试。另报告基础设施敏感性分析，不替换主表。

达到整轮费用/时间上限时停止新任务、保存现场，把未开始样本标记 NOT_STARTED_BUDGET；本批结论“不完整”，不能拿已完成的最好部分宣布通过。完整性破坏、错路由或凭据泄漏立即停批；修复后新批次，旧数据保留。只在安全范围对合成会话做故障注入。

## 10. 可选消融与剂量实验

主实验冻结前选择是否纳入扩展预算；不根据主实验是否获胜临时挑组。每个扩展组采用6族各2个新种子、1次重复=12会话，作为探索性结果：

- D400_INPLACE：与C相同governor几何，仅strategy改为in-place；检查窗口交接的增益/代价。
- C200/C600：应急线200k/600k，R/S及比例不变；用 `E=ceil(T/0.9)`、`W=E+R+S` 计算并以实际取整校验，容量不足记BLOCKED。
- B400_NOPRUNE/C400_NOPRUNE：两组共同关闭修剪器，验证优势是否依赖修剪；不得只关闭一组。
- 无提前提示的机制消融需要先增加独立测试控制，保持400k压力线；当前配置不提供“完全关闭提示但保持其余行为”的已验证开关，不能假造现有功能。不得把改过策略的消融替换正式C组。

## 11. 执行器缺口与实施顺序

现有 `node tests/live/gates.mjs ...` 是历史32k/旧路由实验入口，**不能直接运行来代表本协议**。当前 `run.mjs` 硬编码 `opencode-go`，`model-observer.mjs` 改写Basic阈值/输出且只观察部分主调用，`cohort.mjs`固定9个样本，旧汇总器还绑定旧组语义。新B400不是旧in-place B组。须先完成：

## 12. 证据结构、复核与最终报告模板

私有原始产物统一放在 `.test-runtime/experiments/<protocol-revision>/<batch>/`；包放 `artifacts/`，均被忽略。公开且经过白名单清洗的汇总放 `docs/data/`。不保存模型密钥、认证头、浏览器认证链接/token到可分发证据；原始Web日志/配置不上传。主请求原文仅允许来自合成语料，仍在私有目录；公开只保留字段白名单及hash，发布前检查。

每批至少保存：冻结manifest、environment/installation、完整样本与attempt清单、case-results、请求配置与usage账本、压力轨迹、事件快照、原文重放结果、评分器版本与逐样本成绩、统计脚本/输出、故障明细及sanitization检查。每项带相对路径、SHA-256、时间、协议/候选/宿主身份。每样本至少含 `taskId/family/seed/repeat/arm/sessionId/attemptId/status/routeVerified/configHash/fixtureHash/startedAt/finishedAt/failures`；指标缺失为null并有原因。

状态词固定为 PLANNED、RUNNING、PASS、FAIL、BLOCKED、NOT_EXERCISED、NOT_STARTED_BUDGET；完整性、质量、效率、覆盖分别有状态。流程完成不等于质量通过，源文通过不等于召回通过。公开汇总必须能追溯每个分母，包含失败样本和所有协议偏离；旧报告不被新成功覆盖。

最终报告按以下顺序填写：

1. 精确版本/路由/容量/400k实际几何；执行与未执行范围，费用和总耗时。
2. 三组已分配/已尝试/成功/失败/未开始数；Q1/Q2、更正、交付物、源文和隔离结果。
3. 质量差值及区间、非劣判定；效率用量完整性、成本与时间比及区间；能支持的最窄结论。
4. 首次介入输入、实际换窗次数与触发类型、修剪收益、请求超限及无收益处理；400k是否真正覆盖。
5. R01–R20逐项证据与未覆盖条件，真实物理溢出是否发生；安装卸载、恢复和产物身份。
6. 全部失败与协议偏离、复现实验命令、经清洗数据链接；待修复项或下一轮独立实验。

报告和评分以冻结规则为准。若需要改变产品策略（例如真正的绝对400k换窗开关），作为新候选、新协议修订和完整回归处理，不能用改动后的结果补齐旧候选的失败。
