## 结论

**本地 Qwen 继续工作、Muse 提前准备摘要是可行的。换窗边界可以不等待摘要，并获得更完整的旧历史种子。** 这不是当前产品已经具备的功能：本轮只增加测试层调度原型，没有改动 `src/` 或已安装引擎。目标宿主全程为 **DSH 0.1.2-rc.1**。

九个配对样本和一次真实摘要迟到注入已完成。证据支持继续实现“提前准备、就绪才用、未就绪立即回退”；尚不支持直接上线。产品化前需要解决**快照之后原文的保留**和**种子的实际字节预算**。

## 固定边界：3 个种子 × 3 臂

主模型为本地 Qwen3.8-27B，统一 `reasoningEffort=off`，每次最多 2048 输出 token；独立摘要使用 `opencode-go-muse/muse-spark-1.3-contributor`。顺序为 ABC / BCA / CAB。每个种子使用同一 18 页合成资料（摘要资料正文含页间分隔为 **79,252 字节**），同一前台任务、同一强制安全换窗边界、同一 4096 字节种子上限。归档还包含宿主消息和前台工作，恢复字节数因此更大。原文通过配对工具事件预载；前台工作、摘要和探针均由真实模型完成。

下表是各臂 **3 个样本的中位数**。种子探针的七项包含最新用户更正，以及明确要求摘要省略、必须回原文查找的逐字标记。

| 指标 | A：确定性种子 | B：边界同步摘要 | C：提前准备摘要 |
| --- | ---: | ---: | ---: |
| 边界总耗时，含事务与 flush | 9.51 ms | 4747.95 ms | 7.40 ms |
| 摘要等待／消费检查 | 0.28 ms | 4734.78 ms | 0.30 ms |
| 换窗事务 | 8.39 ms | 12.25 ms | 6.39 ms |
| 种子探针 | 2/7，三次一致 | 6/7，三次一致 | 6/7，三次一致 |
| 开放检索后 | 7/7，三次一致 | 7/7，三次一致 | 7/7，三次一致 |
| 成功执行的历史检索次数 | 9（原始 5/9/10） | 10（11/10/2） | 3（3/3/2） |
| 检索阶段耗时 | 46.41 s | 71.51 s | 36.81 s |

C 的边界范围为 **7.21–9.18 ms**；不能把它和 A 的几毫秒差异解释成确定性算法加速。核心结果是它没有 B 的 **4.63–6.35 秒**等待。C 的真实云摘要流与本地主流分别重叠 **4.633 / 5.644 / 5.347 秒**，全部完成；完整流审计确认正式样本的本地请求串行、没有自动标题请求。这证明请求可以同时推进，不是服务端 GPU 并行方式的证明。

本轮 C 的检索次数更少，但总体成本不能保证降低：B 前两个样本反复核验摘要中已有事实，用了 11、10 次检索；C 第二次检索阶段也耗时 64.82 秒。样本少、生成有波动，且诊断阶段可能发生被拒绝的工具尝试，不能宣称统计显著或一般任务的端到端加速。数据单列成功检索和被拒绝的尝试。

## 迟到与安全性

一次 C 故障样本使用真实 Muse 调用，但在测试层扣住完成结果，直到换窗之后才交付。边界观察到 `pending`，消费检查 **0.41 ms**，事务 **17.53 ms**，立即采用抽取式种子。随后结果以 `late` 结束，未追写窗口；最终账本仍只有一次换窗。种子 2/7，检索后 7/7。

十个完成的边界样本均通过：日志追加式、当前用户输入未归档、工具配对平衡、归档所有文本块逐页恢复且字节一致、本地请求串行。Web `session/page` 是折叠后的 UI 页面；审计使用观测器的完整连续日志，并核对每个 UI 返回事件，而不把 UI 页面误当完整日志。

调度状态机的七项测试覆盖一次性消费、迟到、会话/代数/来源/路由失配、取消与销毁、错误/空/超长摘要、超时、流时间区间计算。**取消、销毁、服务错误和失配只有单元覆盖，没有伪称已做真实云端故障测试。** 实验控制器强制换窗；这些 `model-assisted` 记录不代表主模型自愿调用 `new_context`。

## 两个需要进入产品设计的约束

### 1. 只替换摘要覆盖的前缀，保留后续原文

当前固定边界原型会把摘要快照之后的前台输出也归档，但摘要没有看过它。九个样本的探针不考这些新增事实，所以 7/7 不能替这部分连续性背书。

独立的真实宿主事务离线实验加入一条快照后的新事实：直接走当前完整前缀换窗时，该事实离开可见表面；改用共享事务只替换快照覆盖的前缀时，该事实原文仍在表面。两条路径都保持日志追加式与代数正确。这个替换范围机制已经离线验证，**尚未集成成引擎功能或跑完整模型门**。

建议新窗口结构：**旧前缀的确定性索引 + 已就绪且带来源的摘要 + 快照之后的原文 + 当前用户输入**。替换范围必须落在平衡工具边界；仍不足以缓解压力时走确定性回退，不等待云端。

### 2. 使用实际剩余字节预算

真实 Muse 摘要为紧凑的 185 字符 JSON；在 1/12/24/48 条历史用户输入的索引压力下，六个字段全部保留。另将交接文本扩为 **1300 字符的合成压力样本**，把事实放在末尾：四种历史规模都触发截断，末尾六项事实全部丢失。原文仍可恢复，产品也标出了截断，但固定 1400 字符上限不能保证摘要完整进入 4096 字节种子。

产品调度器应先分配用户索引、原始记录和原文尾部预算，再给摘要实际可用的 UTF-8 字节额度；记录最终被保留的字段和来源，不把请求成功等同于摘要成功接入。
