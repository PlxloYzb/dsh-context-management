# 历史检索索引设计合同

状态：**已按评审决定修订，进入实现**。
适用范围：`ArchiveReader.search` 及其索引。**不扩展摘要生成与换窗策略**。
本轮目标：查询语义可靠、工作量有界、可增量加速的**历史读取层**。

## 0. 为什么写合同而不是继续调参

动机全部来自实测，不是推理：

| 观测 | 数值 | 结论 |
|---|---|---|
| 单发命中（封存归档 12 探针） | 5/12 → 4/12 | 块级过滤器诚实计费后反而退化 |
| 单发撞预算 | 12/12 | 从未改善 |
| 沿游标命中 | 11/12 | 唯一可用路径仍是翻页 |
| 首次建索引字符数 | 74,259,292 | 唯一原文约 268 万，差额来自嵌套逐层重复索引 |
| 一条 checksum 查询留下的候选块 | 64/64 | 该查询在块粒度上无法收窄 |

由此确定三条设计方向：**按唯一原始事件建索引**以避免重复；**索引只产生候选**，最终命中仍按既有字面量语义核验；**索引只加速**，不改变任何语义。

## 1. 范围内 / 范围外

**范围内**：索引数据模型、候选生成、归属与去重、游标、归档范围、预算与计量、验收指标。

**范围外**：摘要生成（原生负责）；换窗时机与 ARC 策略；新增独立服务或包。

**职责边界（本轮明确）**：历史读取**不得依赖 ARC 的主动压缩策略**，也**不得为了读取 Basic 的历史而接管其压缩后端**。独立能力留在本仓库、同一个插件包内，拆成清晰模块即可。

## 2. 索引单位与构建方式

- **单位是 `(seq, textBlockPath)`**：`seq` 为原始事件序号，`textBlockPath` 为 `eventTextParts` 给出的块内路径。
- **`seq → 可产出它的块` 另设多对多关联**，由 ledger 派生。块只用于确定命中归属，不作为索引单位。
- **按需、分段、跨调用增量构建**。唯一事件索引**不等于**首次必须读完整档。
- **未完成的索引只表示「未知」**，不得据此排除任何来源。
- 「与嵌套深度无关」**仅**用于描述「避免对同一份原文按父归档层数重复建索引」这一项成本。**来源图解析**（`sources()` / `resolveIndexedSources`）与**归属维护**（`owners`）必须**单独计量**，不承诺总成本与深度无关。

## 3. 候选生成与键

- 索引**只产生候选**。命中最终一律按**既有字面量匹配语义**核验：同一 `foldCase`、同一分块读取、同一重叠处理（命中后按一个标量前进，允许重叠出现）。
- **完整的 token 索引不得漏掉合法的子串查询**。查询不限于完整 token：实体 ID、文件路径、错误文本、中文、部分值都必须在支持范围内。
- **无法安全加速的查询回退扫描**，并在响应中说明。
- **停用键**：出现频次过高的片段不入索引，该查询回退扫描。阈值 τ 依**实测频次分布、候选数量与内存成本**确定，20% 仅作实验起点，不作为合同常量。
- **删除**此前「公共前缀使整串 3-gram 在数学上无法排除」的表述——**公共前缀不是充分原因**，值内片段仍可排除候选。实测遇到的问题是**部分值片段本身也很常见，叠加块粒度过粗**。

## 4. 归属与去重（保留既有语义）

既有实现：`owners: Map<seq, blockIndex>`，按会话 `WeakMap` 持久化，跨调用与跨游标页有效；逐 seq 判定 `owner < b` 则跳过，否则在 `(owner === undefined && owners.size < 200_000) || (owner !== undefined && b < owner)` 时认领。

**不变量**：

- **I1（等价性）**：在**同一会话快照、同一查询语义、同一初始状态**下，**完整分页之后**命中**位置与归属一致**，至少包含 `(seq, path, offset)`。**不接受**只比较 `seq` 集合。索引消耗预算会导致**每页切分不同**，这是允许的；不允许的是最终结果不同。
- **I2（记账独立）**：索引只决定是否读取文本。被候选阶段排除的块仍照常认领其全部 `sources.seqs` 并计入 `inspected`。
- **I3（容量行为）**：**已跟踪来源**维持原有的**最低块归属**；**超出容量（20 万）的来源**沿用 **「允许重复、不允许遗漏」**。I3 与 I4 不冲突——二者分别约束「已跟踪」与「超出容量」两种情形。
- **I4（最低块归属）**：在已跟踪范围内，同一 `seq` 只在能产出它的**最低块**索引下报告，跨游标翻页与重复查询亦然。

## 5. 文本语义

- **I5（同一折叠）**：扫描、查询与索引共用同一个 `foldCase`，且必须**上下文无关**（逐码点）。只有上下文无关才能保证折叠与拼接可交换，使「任一分块的 gram ⊆ 其所在片段被索引的 gram」成立。
- **I6（候选超集）**：除明确声明的停用键外，索引候选必须是扫描条件的**超集**。碰撞只允许多读，不允许漏命中。**最终命中一律以字面量核验为准**。
- **I7（absent 前提）**：仅在**全部**满足时允许给出 `absent`：
  1. **零命中**；
  2. **查询范围已穷尽**（无待续游标，即本次自 0 起扫且已到末尾）；
  3. **无未解决的来源缺失**（`sources.incomplete` 为假、无 `missing`）；
  4. **无预算截断**（`scanBudgetReached` 为假）；
  5. `inspected > 0`。
  
  **未索引内容或停用键，只要已通过完整扫描核验，就不再算作覆盖缺口**；反之，未核验的部分仍算缺口。
  **保留保守规则**：续页（带游标的一页）**不得独立宣告全档不存在**。

## 6. absent 的范围与措辞（修正第 8/9 节矛盾）

- 归档只含**被遮蔽的原始事件**；**当前窗口不在归档搜索范围内**。
- 因此当目标只存在于当前窗口时，在**完整查遍归档**后**允许**返回明确限定范围的结论：

  ```json
  { "absent": true, "scope": "archived_history" }
  ```

- **不得**声称整个会话不存在该内容，**也不得**暗示应放弃当前窗口中的证据。
- 验收检查的是**范围表述是否正确**，**不是一律禁止 `absent`**。
- p288 即此类实例：目标 `seq 5478`（`tool/result`）仍在当前窗口，非归档来源。

## 7. 预算与计量

- 每次调用共用一份 `WORK_BUDGET`；**建索引与扫描计入同一预算**。
- **开工前判定负担能力**（量长度几乎免费），负担不起的内容**根本不建索引**，而不是先建后弃——实测先建后弃会让整页预算耗在一次建不完的索引上（110 万字符的块使首页只前进 16384 字符）。
- 除索引与扫描的文本量外，还必须约束并计量：**来源图遍历**、**候选处理**、**临时内存**、**取消检查**。
- 必须**分别报告**：冷查询（索引未就绪）、热查询（索引就绪）、完整分页（翻到末尾）的**成本与命中情况**。
- 响应必须可区分「未测」与「不存在」，并报告本次是否命中索引、读取字符数、是否因预算截断、是否因停用键回退。

## 8. 游标合同（如实描述既有实现）

既有行为，本轮**不改变**：

- 游标体经 HMAC 签名，绑定 `session.id`、`scope = search:<query>:<limit>` 的哈希、`anchor = session.seq`、`fingerprint`。
- `fingerprint(events, anchor)` 只哈希**锚点处的那一个事件**（`events[anchor-1]`）。
- 失效条件为：**会话已缩到锚点之下**（`anchor > session.seq`），或**锚点处事件已被改写**（指纹不符）。
- **在锚点之后追加事件不会使游标失效**——绑定的前缀仍然有效，续页行为照常。**不得**把合同写成「anchor 后有追加即失效」，也不得顺带改变该行为。

**新决策（已确认）**：游标**不绑定索引缓存代数**，前提是索引始终只加速：不改变查询语义、遍历顺序、来源范围与 offset 含义。必须补充回归验证：**构建中继续旧游标**、**淘汰后继续旧游标**、**重建后继续旧游标**三种情形下续页仍正确。

## 9. 缓存合同

- 本轮采用**进程内、会话隔离、按需增量构建**的缓存；**不做磁盘持久化**。
- **原始会话事件是唯一事实来源**；缓存可随时丢弃并重建。
- 必须明确并测试：**容量上限**、**淘汰策略**、**取消**（AbortSignal）与**销毁**行为。
- **不得使用隐藏的全局会话状态**。

## 10. 归档范围失效

索引只覆盖归档原文。当来源被恢复出窗（换窗回滚、窗口还原）时，其索引条目必须失效或整体作废。

**实现结论（2026-09-16）**：正确性上**不需要**失效，只需要释放内存。索引查找由**当前 ledger 解析出的来源集**驱动——`seqMayContain` 只会对本次 `sources.seqs` 里的 `seq` 被调用，因此某个已不在任何块来源中的 `seq`，其残留条目**永远不会被查询到**，既不改变命中也不改变归属，只占内存。因此释放由 `disposeIndex(session)` 承担，它同时是内存手段与可观测手段。

**尚未构造的验证**：`region.ts` 中**未找到公开的出窗/回滚 API**，所以"来源恢复出窗后索引行为不变"这一场景**目前无法写成测试**。这一点如实记录，不声称已验证。

## 11. 验收

**查询族**（替换现有 12 条「拿完整值反查」探针）：

| 族 | 意图 | 期望 |
|---|---|---|
| 实体 ID + 字段 | 已知 ID、未知字段值 | 首轮命中 |
| 文件路径 + 错误 | 已知路径、找错误上下文 | 首轮命中 |
| 旧版本 vs 新版本 | 定位变更前后 | 两者均可定位 |
| 仅部分前缀的未知值 | 知道前几位 | 允许未命中，但必须可翻页 |
| 仅存在于当前窗口 | 边界 | `absent` 必须限定 `scope: archived_history` |
| 中文与多字节 | 边界 | 命中且 offset 正确 |

**对照臂**：Basic + 历史检索 vs 现有 ARC 策略。

**通过条件**：
- present 字面量相对 0.3.1 扫描路径**无退化**；
- `absent` 仅在 I7 全部满足时出现，且**范围表述正确**；
- 冷/热/完整分页成本与命中**分别报告**。
